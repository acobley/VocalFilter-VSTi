VocalFilter — signal path

Three bandpass resonators in parallel per channel. Drawn from Dsp::process and VocalFilterProcessor::pushParameters. The two channels are identical and share coefficients; only their filter state differs, so one is drawn.

F2 is summed inverted

A bandpass runs from +90° below its centre to −90° above, so between F1 and F2 the two branches are half a turn apart. Summed with the same sign they cancel, digging a null an all-pole tract does not have — measured at −20.4 dB against −8.5 dB inverted.

Dropping the inversion leaves every peak exactly where it is and moves only the valleys, which is why the test for it looks at a valley.

Vowel is a mode, not a recall

While it is on a preset the DSP takes that vowel's nine values and the nine parameters are ignored. The processor reads it, not the controller, so it works with the editor closed, offline and under automation.

Touching a formant slider captures the preset's values into the parameters and switches back to Manual, so nothing jumps.

The display reads published values

It follows the gliding values, which live in the processor, so they cross to the controller as nine read-only hidden parameters. Not a message: a message sent from process() is silently discarded by the host's connection proxy.

The sample rate does travel by message, from setActive, where the UI thread makes one legal.
